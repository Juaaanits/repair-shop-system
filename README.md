# Anton Fix Appliances Repair

A job order management application for an appliance repair shop. The planned workflow covers customer intake, repair management, customer notification assistance, and printable job order slips.

## Implementation scope

The foundation milestone (M1) provides owner authentication, a protected administration page, a PostgreSQL schema, migrations, and initial account and settings data. Customer intake, job management, printing, settings editing, and PWA installation support are planned milestones and are not yet implemented.

See the [MVP plan](docs/mvp-plan.md) for scope and acceptance criteria. Development proceeds one milestone at a time.

- Node.js 24 LTS, as specified in `.nvmrc`
- npm and Git
- Docker with Compose, or an accessible hosted PostgreSQL database

When nvm is installed, run `nvm install` and `nvm use` from the repository root to select the project runtime.

## Local setup

### 1. Install dependencies

```bash
npm ci
```

### 2. Configure the environment

Create `.env` from the template if it does not already exist:

```bash
cp .env.example .env
```

Generate an authentication secret:

```bash
openssl rand -base64 32
```

Set the following values in `.env`:

| Variable         | Purpose                                                                       |
| ---------------- | ----------------------------------------------------------------------------- |
| `DATABASE_URL`   | PostgreSQL connection string; the template matches the local Compose database |
| `AUTH_SECRET`    | Secret generated by the command above                                         |
| `AUTH_URL`       | Application URL; `http://localhost:3000` for local development                |
| `OWNER_EMAIL`    | Email used to create the owner account                                        |
| `OWNER_PASSWORD` | Initial owner password, at least 12 characters and at most 72 UTF-8 bytes     |
| `OWNER_NAME`     | Owner display name; defaults to `Anton` when omitted                          |

Environment files contain credentials and must remain outside version control. Commit only the sanitized `.env.example` template.

### 3. Initialize the database

For local PostgreSQL:

```bash
npm run db:up
npm run db:migrate
npm run db:seed
```

For hosted PostgreSQL, configure `DATABASE_URL` with the provider's connection string and required TLS parameters, then run the migration and seed commands without `db:up`.

The local database is bound to loopback and uses a persistent Docker volume. Its example credentials are intended for development only.

Seeding preserves existing accounts and settings. Changing `OWNER_PASSWORD` and rerunning the seed does not reset an existing password. Use one consistent owner email; the application does not provide account management or a password reset interface.

### 4. Start the application

```bash
npm run dev
```

Open [the owner login page](http://localhost:3000/login). The protected `/admin` page contains the foundation placeholder until job management is implemented.

## Validation

Run the local checks before submitting changes:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

The credential unit tests use mocked database queries. Validate database initialization, successful and unsuccessful login, sign-out, and unauthenticated access to `/admin` against a configured development environment before merging authentication changes. Include results in the pull request rather than committing verification reports.

## Project structure

```text
src/app/               Routes, pages, and server actions
src/server/services/   Application logic and credential validation
src/server/db/         Database schema, connection, and queries
src/auth.ts            Auth.js configuration
scripts/               Database migration and seed entry points
drizzle/               SQL migrations and schema metadata
docs/                  Product scope and contributor documentation
```

Routes and UI call services, and services access the database layer. Future mutations must validate input on the server, and each administration page and action must check the session on the server.

## Architecture notes

- Auth.js Credentials uses bcryptjs password verification and JWT sessions with an eight-hour lifetime. The pinned Auth.js v5 integration is a prerelease; review compatibility when upgrading.
- PostgreSQL stores timestamps with time zones and monetary values as integer centavos. Job records include a warranty-day snapshot, and customer phone numbers are unique.
- The seed inserts missing records in a transaction and preserves existing data. Shop address and phone are initially empty; review shop details and terms before operational use.
- Next.js generates `next-env.d.ts` locally. Type checking generates route declarations first, and automatic agent-rule generation is disabled to preserve project instructions.
- Direct dependencies are pinned. Commit SQL migrations and Drizzle metadata together, and review dependency updates and audit findings explicitly.

The foundation is not a production release. Job workflows and the planned security hardening remain incomplete. See the MVP plan for release scope.
